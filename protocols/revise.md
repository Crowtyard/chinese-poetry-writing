# protocols/revise.md —— 修改协议（v0.1-beta / STEP 2）

来源：protocols/critique_v2_candidate.md 修改纪律层、revision_discipline（保诗眼优先于修律）、evidence/user_aesthetic_evidence.md（提炼）。

## 修改优先级（只许从高到低动，不得跳级）

1. 诗眼（POETIC_EYE）—— 全诗为什么而写的那一个核心（发现/关系）。
2. 关系 —— 物象之间做功的连接（删任一方另一方即损）。
3. 不可替换事实 —— 只属于"这一首"的物件/时间/人物细节。
4. 自然语言 —— 句法、语序、用词、节奏。
5. 格律 —— 最后才修律；只动违规处。

原则：低层改动不得损伤高层。任何一次改动若伤及 1-3 层，先撤销再另寻改法，不"以律害意"。

## 每次改动的记录义务

对每一处实质改动记录：
- POETIC_EYE_PRESERVED = TRUE / FALSE
- NATURAL_SYNTAX_PRESERVED = TRUE / FALSE
任一 FALSE → 撤销该处改动，重写；连续两次 FALSE → 该修改方向作废，换方案或回 compose 换 CONCEPT。

## 语言层修订规则

- 为避开「的」而伪文言/生硬倒装 → 禁止。找不到自然替代，且六问通过 → 保留该「的」。
- 换词从"首选自然表达"出发；韵脚是最后约束，不得为韵选择偏离首选表达的词。
- 删解释句前先确认：物证链是否仍在？删后读者能否自补（留白），还是变谜语（缺失）？
- 缺推断锚点时优先补一个物理证据（动作/痕迹/声音），不补修辞词。
- 保持白描 ≠ 把诗改得更"雅"：语言方向只有"更准确、更自然"。

## 修律纪律（与 chinese-poetry-prosody 协作）

- 只改验律报告指出的违规处（失粘/失对/出韵/字数等）；报告外不动。
- 迭代上限 5 轮；每轮改后复检，记录中间版本，不隐藏。
- 诗意与格律不可兼得时，如实报告冲突，不强行凑合（PASS 不是审美合格；冲突时保诗眼，冲突项留给用户裁决）。
- 修律完成后必须过一遍语言复检：改韵/调序是否引入解释、套话、倒装。

## 分层回退（REVISE 无效时的出口）

- 语言层改不动 → 回 CRITIQUE 重新定位根因（可能批评没落到句）。
- 构思层根因（无发现/关系单薄）→ 语言微调无法修复，回 COMPOSE 换 DISCOVERY/CONCEPT，禁止在同构思上掩盖。
- 用户已裁决的偏好/反例是软参考：不得为了迎合某一结构而推翻本协议的高层优先级。
